Rules for anyone building this

  • Retro stops at the plot area. Bevels, gradients, and title bars are period-correct. Charts, numbers, and logs are contemporary and legible. Screenshot any window and ask whether the content looks credible.
  • Every OS affordance carries product meaning. Desktop icons are installed mini apps. The taskbar is running agents. The tray is background autonomy. End Task is the kill switch. Nothing is decorative.
  • Form follows data. The gauge above exists because a health factor is a bounded ratio — not because anyone typed "gauge". Every component in the catalog needs a selection rule that reaches it.
  • Autonomous apps always render policy_badge and trade_log. An agent that spends money shows its work. Neither is optional.
  • Chrome is CSS, not the catalog. A2UI components are semantic; the XP look is one theme over them. The theme swap must keep working — it is what proves the agent never knew what it looked like.
  • Below 768px: windows become full-bleed sheets keeping their title bars, the desktop becomes an icon grid, the taskbar pins to the bottom, and drag/resize/z-order is dropped entirely.
  • Motion: windows scale open, minimize toward the taskbar, balloons slide from the tray. Nothing else. Honour prefers-reduced-motion. Keep XP's dotted focus outlines — period-correct and genuinely accessible.

Build notes

  • npm i xp.css gives authentic chrome and form controls as pure CSS. It does not ship a window manager — drag, resize, and z-order need react-rnd or equivalent. That is W5b's work, not a styling pass.
  • This file is hand-written so the chrome is readable and portable. Match these tokens exactly; borrow the markup patterns freely.
