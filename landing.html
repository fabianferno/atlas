The Problem

Tooling is powerful.
But it's siloed.

The Graph has built incredible agentic tooling — MCP servers, x402 payments, A2A integrations, standardized subgraphs, Substreams. But builders create one-off tools that don't connect to each other. There's no shared surface to create, share, and discover reusable mini apps.

🧩

Siloed Tooling

Builders create dashboards, agents, and tools in isolation. No shared ecosystem to discover and reuse.

🎨

Static Dashboards

Current tools show data on pre-built pages. No dynamic, agent-generated UIs that adapt to queries in real-time.

🔑

No Shareable Format

A dashboard you built stays yours. There's no "dashboard as code" — a shareable prompt, query, and UI spec.

Mini App Runtime

The core rendering layer. Agents describe UI in natural language → A2UI framework renders live, interactive components. Data binds to The Graph subgraph queries so everything updates as onchain data changes.

  • A2UI component generation from natural language prompts
  • Live data bindings to The Graph subgraph queries
  • Pre-built component library: charts, tables, balance cards, leaderboards
  • Snapshot mode for shareable point-in-time renders
  • Fork & remix any mini app with modified queries or prompts
A2UI Components Live Data Bindings Snapshot Mode Fork & Remix
Example

"Show me Uniswap V3 revenue on Arbitrum for the last 7 days" → Agent generates an A2UI bar chart + data table, data binds to Standardized DEX schema → live chart with clickable bars for details.

Connected to
← Graph Integration (data) → Registry (publish) → Agent Intelligence (generation) → 0G (inference)
📋
Mini App Registry

A catalog where mini apps are published and discovered. Every app is defined by prompt, query config, UI spec, and metadata — making it a truly shareable "dashboard as code" artifact.

  • Publish with prompt, query config, UI spec, and metadata (author ENS)
  • Discover / browse with filters by category, chain, protocol, or tag
  • One-click instantiate: runs prompt + queries and renders A2UI
  • Community ratings for usefulness, accuracy, and design
  • Versioning when prompts or queries change
Publish Discover Rate & Review Versioning
Example

"Arbitrum DEX Revenue Comparator" — published with prompt, Standardized DEX schema on Arbitrum, tagged #defi #arbitrum #dex, used by 142 institutions, rated 4.7/5.

Connected to
← Runtime (consumes) → ENS (identity) → Agent Intelligence (suggestions) → Graph Integration (query config)
🔗
The Graph Integration

Deep integration with The Graph's data and AI tooling — subgraph studio, MCP aggregation, x402 pay-per-query, standardized auto-binding, Substreams streaming, and cross-protocol routing.

  • Subgraph Studio integration with auto-configured API keys
  • MCP Server Aggregation — unified interface across lending, DEX, CDP
  • x402 Pay-per-Query — authors earn per query
  • Standardized Subgraph Auto-Binding to Messari schemas
  • Substreams Data Streaming for real-time dashboards
  • Cross-Protocol Query Router — one prompt, multiple subgraphs
Subgraph Studio x402 MCP Substreams
Example

"Total value locked across all lending protocols on Optimism?" → Resolves to Standardized Lending Subgraph → queries Subgraph Studio → aggregates TVL across Aave, Morpho → renders TVL card.

Connected to
→ Runtime (feeds data) → Agent Intelligence (resolution) → Registry (query config) → 0G (payment)
🧠
Agent Intelligence Layer

The reasoning layer — agents that understand queries, compose data from multiple sources, remember user preferences, auto-recommend, and deploy via SKILL-based one-prompt deployment.

  • Query Intent Parser — maps natural language to subgraph schemas
  • Multi-Source Compositor — combines multiple subgraphs/MCPs into unified view
  • Agent Memory — remembers preferences, past queries, interactions
  • Auto-Recommendation — suggests relevant mini apps based on patterns
  • SKILL-Based Deployment — one-prompt deployment
Intent Parser Memory SKILLs Auto-Rec
Example

"I've been looking at GMX on Arbitrum. What's the top perp DEX by open interest?" → Remembers GMX query → resolves perpetuals schema → queries data → renders comparison mini app → suggests tracking over time.

Connected to
→ Runtime (generates UI) → Graph Integration (queries data) → Registry (recommends) → 0G (memory storage)
🏷️
ENS Integration

ENS-powered identity and discovery — mini apps get ENS subnames, metadata stored in text records, agents resolve identities via onchain ENSIP-25 verification, and agent fleets register subname trees.

  • Mini App ENS Names — e.g., "top-dexs.graph.eth"
  • ENS Text Records for app/prompt, app/query, app/version, app/author
  • Agent Name Resolution — resolve ENS → protocol identity & metadata
  • Subname Registry for Agent Fleets — "agent-a.graph.eth"
  • ENSIP-25 Agent Verification via onchain name ownership
  • ENSIP-26 Agent Text Records — standardized metadata
Subname Registry Text Records ENSIP-25
Example

Agent resolves "dex-comparator.graph.eth" → looks up text records → fetches prompt and query config → instantiates mini app with live Graph data.

Connected to
→ Registry (identity) → Runtime (name resolution) → Agent Intelligence (fleet mgmt) → 0G (Agentic ID)
🔒
0G Integration

0G-powered inference, storage, and verifiable compute — sealed inference for private queries, encrypted agent memory, micropayments on 0G Chain, and cryptographic proof of model provenance.

  • Sealed Inference via 0G Private Computer (TEE-sealed)
  • 0G Storage for encrypted agent memory persistence
  • Agentic ID for mini app authors on 0G
  • Onchain Micropayments via 0G Chain (x402 + 0G)
  • Verifiable Model Provenance — cryptographic proof of inference
TEE Sealed 0G Storage Provenance
Example

Private portfolio risk analysis → wallet kept private via TEE → agent queries Graph for holdings → inference runs on 0G → results rendered as risk dashboard. Wallet never leaves the TEE.

Connected to
→ Runtime (render) → Agent Intelligence (memory/inference) → Graph Integration (payments) → ENS (Agentic ID)
